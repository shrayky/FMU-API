# Загрузка документа ТСД

Срез после проверки связи `docs/tsd-exchange-protocol.md`. Скан штрихкода документа сохраняет новый документ и обновляет справочники в `main.db`. Подбор марок и выгрузка сюда не входят.

`hs` в путь не добавляется. Его пишут в публикации вместе с именем базы, например `ideal1/hs`.

## Запрос

Команда уже есть в `ExchangeProtocol.documentByBarcode`. Для сбора передаётся `markCollectionDocumentCommand` (`СборМарокПоДокументу`). Имени `Async` нет.

Живой вызов у `DS TСД`:

`GET {схема}://{адрес}:{порт}/{публикация}/dstsdapi/get?Команда={команда}&Штрихкод={штрихкод}`

Схема, публикация, basic-авторизация и таймаут — те же, что у ping. Параметры запроса кодирует `Uri`. Пустой адрес, порт 0 и таймаут 0 в сеть не уходят, тексты те же, что у проверки связи.

Сервер — выбранный в настройках `exchangeServerId`. Если он не выбран, запрос не отправляется: «Не выбран сервер обмена». Data Mobile сеть не вызывает и возвращает «Протокол Data Mobile ещё не подключён».

Успех HTTP — код 200. Тело читается как UTF-8. Другой код и сбой соединения — ошибка, база не меняется. Один `try/catch` в реализации команды.

## Разбор тела

Флаги `Результат` не читаются. Документ есть, если массив `Пакет.Данные.Документы` не пуст. Берётся первый элемент. Пустой или отсутствующий массив — «В полученном пакете отсутствует документ!», база не меняется.

Документ:

| Поле | Смысл |
|---|---|
| `УИД` | идентификатор ERP, в колонку `erp_uid` |
| `Представление` | колонка журнала «Документ» и колонка `presentation` |
| `Тип` | в примере `СборМарок`; ключа `ТипДокумента` в ответе нет |
| `БезПроверкиВладельца` | остаётся в JSON тела |
| `Состав` | строки документа, остаются в JSON тела |

Строка состава: `Номенклатура`, `Количество`, `Маркированный`, `КоличествоМарок`, `Цена`, `Сумма`, `ЗаказаноКоличество`, `ПодбораноПоЗаказуПолностью`. `Номенклатура` строки — УИД товара.

Справочники лежат в `Пакет.Данные.Справочники`. Пишутся только непустые массивы `Номенклатура`, `Штрихкоды`, `РазмерыУпаковок`. Остальные ключи этого среза не читаются.

`Весовой` в живом ответе — строка `"false"`. В базу кладётся как пришло, без приведения к логическому типу.

`Номер` и `Контрагент` в примере отсутствуют. Если ключ есть в объекте документа — значение идёт в колонку поиска. Если нет — колонка пустая. Номер и дату из текста `Представление` не разбираем.

## База

Файл `main.db` в каталоге баз приложения, класс `infrastructure/documents/main_database.dart`. Журнал работы остаётся в `journal.db`. Чистка одного файла другой не трогает.

`infrastructure/documents/sqlite_document_store.dart` открывает эту базу. В тестах фабрика подменяется, как у `JournalDatabase`.

Таблица `documents`. Одна строка — один скан. Повторный `УИД` ERP создаёт новую строку.

| Колонка | Зачем |
|---|---|
| `id` | ключ документа ТСД |
| `scanned_at` | момент скана, миллисекунды; срок хранения и колонка «Дата» |
| `number` | `Номер`, иначе пусто |
| `counterparty` | `Контрагент`, иначе пусто |
| `presentation` | `Представление` |
| `erp_uid` | `УИД` |
| `body` | JSON объекта документа, включая `Состав` |

Индексы по `scanned_at`, `number`, `counterparty`. Позиции отдельной таблицей не хранятся.

Справочники в той же базе. Тот же ключ перезаписывает строку. Срок хранения их не удаляет.

| Таблица | Ключ | JSON |
|---|---|---|
| `nomenclature` | `uid` = `УИД` | карточка товара |
| `barcodes` | `barcode` = `Штрихкод` | карточка штрихкода; в колонке `nomenclature_uid` тот же УИД, что в поле `Номенклатура` |
| `pack_sizes` | `nomenclature_uid` = поле `Номенклатура` | размер упаковки; `ЕдиницВУпаковке` внутри JSON. Срез `docs/tsd-mark-pick.md` делит строку на упаковку и палету флагом `Паллета` |

Запись справочников и вставка документа — одна транзакция. Ошибка посередине не оставляет половину пакета.

## Срок хранения

Поле `documentRetentionDays` в `AppSettings`, по умолчанию 30. На вкладке «Основные» поле «Сколько дней хранить документы» стоит рядом с сервером обмена и пин-кодом, до группы «Документ Сбор марок».

Ноль документов не удаляет. Число больше нуля удаляет строки `documents`, у которых `scanned_at` старше этого числа дней. Срез выполняется после удачной загрузки и при открытии журнала. Сбой среза не отменяет уже сохранённый документ: иначе повторный скан QR создал бы второй документ.

## Экраны

Журнал `presentation/mark_collection/mark_journal_screen.dart` читает `documents` по `scanned_at` по убыванию. Колонка «Документ» — `presentation`. «Выгружен» пусто, пока выгрузка из `docs/tsd-mark-pick.md` не поставит отметку. «Номер» — `number`. «Дата» — день скана. Поиск фильтрует по `presentation`, `number` и `counterparty` без учёта регистра. Строка открывает этот документ. «+» открывает новый сбор без документа.

Новый сбор на шапке принимает штрихкод и показывает уже существующий экран «Ожидание...». «Отмена» закрывает клиент и ничего не пишет. После ответа экран закрывается.

Успех открывает состав: наименование из `nomenclature` по УИД строки, количество — `Количество`, марок — `КоличествоМарок`. Нет карточки товара — наименование пустое, строка состава всё равно видна.

В уже открытом документе штрихкод документа загрузку не запускает. Пункт меню «Сбор марок» и «+» журнала открывают пустой сбор. Строка журнала открывает уже сохранённый документ.

## Проверка

Тесты `flutter test` в `src/Presentation/TsdApp`:

- ds-tsd собирает URL `.../ideal1/hs/dstsdapi/get` с командой `СборМарокПоДокументу` и штрихкодом, когда публикация равна `ideal1/hs`;
- пустой `Документы` не пишет в базу и возвращает «В полученном пакете отсутствует документ!»;
- пакет из примера вставляет одну строку документа и обновляет товар, штрихкод и размер упаковки по ключу; повтор того же пакета добавляет второй документ и не плодит вторую карточку товара;
- `Весовой` сохраняется строкой `"false"`;
- срок 30 удаляет документ старше 30 дней и не удаляет справочник; срок 0 не удаляет документ;
- сбой среза срока хранения не отменяет сохранённый документ;
- Data Mobile сеть не вызывает;
- отмена ожидания не создаёт документ.
