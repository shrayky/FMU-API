# Подбор марок и выгрузка

Срез после загрузки документа `docs/tsd-document-load.md`. Скан марки пишет строку в `marks` и меняет «Подобрано». «Выгрузить документ» отправляет пакет на сервер обмена. Полная загрузка номенклатуры, новая цена и Anydesk сюда не входят.

Пока документа нет, марка загрузку не запускает. Ждётся QR документа.

## Настройки

Четыре поля группы «Документ Сбор марок» на «Основных».

«Регистрация штрихкода упаковок (по умолчанию)» открывает позицию в режиме «Упаковки». Кнопка на позиции переключает подпись на «Единицы и упаковки» и обратно. В режиме «Упаковки» марка с одной единицей не пишется: «Нельзя сканировать индивидуальные марки!».

«Проверять владельца марки» действует, когда у документа `БезПроверкиВладельца` ложь. Запрос — `POST {адрес Fmu-Api}/api/ts/checkMark`, тело — JSON-массив из одной марки. Код не 200 считает марку чужой. По каждому элементу `Codes`: если `IsTracking` истина, владелец — `IsOwner`, иначе марка наша. Чужая не пишется: «Марка этого товара не принадлежит нам, ее нельзя подобрать!».

«Запрос статуса подбора марки» при том же условии документа: `GET {публикация}/dstsdapi/get?Команда=СтатусСбораМарки&Марка={марка}`. Марка пишется, когда `Данные.Успех` истина. Иначе показывается `Ошибка` из `Данные`, а если её нет — «Неверный формат ответа на команду проверки статуса марки!».

«Запрашивать упаковку марки по true api» работает в режиме «Упаковки», когда у марки одна единица и «API для проверки марки» равно «True api». Токен: если задан адрес проверки марок — `GET {адрес}/api/ts/token`, поля `token` и `expired`; иначе `GET` сервера обмена с командой `ТокенТруАпи`, поля `Токен` и `ДействуетДо`. Просроченный токен — «Срок полученого токена истек!». Из ответа статуса марки берётся `Упаковка`. Непустая упаковка проходит тот же разбор ещё раз, проверка владельца для этого повтора пропускается. Пустая упаковка оставляет запрет индивидуальной марки.

`hs` в путь не добавляется. Пустой адрес, порт 0 и таймаут 0 в сеть не уходят, тексты те же, что у проверки связи. Data Mobile сеть не вызывает и возвращает «Протокол Data Mobile ещё не подключён».

## Скан

Штрихкод из 13 цифр только открывает позицию. Марку он не пишет.

Перед подбором марки документа читаются из `marks`. Если чтение не удалось, подбор не открывается, а скан показывает «Не удалось прочитать марки документа»: с нулём в «Подобрано» марка прошла бы проверку `Количество` и записалась бы сверх состава.

Сканы идут по одному: пока марка не записана, следующий код не принимается. Иначе проверка `Количество` увидела бы прежнее «Подобрано» и записала лишнюю марку.

Марка при открытом документе идёт по порядку:

1. Код с `000` — палета. Код с `00`, но не с `000` — упаковка.
2. Владелец и статус, если настройки их включают.
3. У кода, который не упаковка и начинается с `01`, штрихкод товара — 13 символов с четвёртой позиции. У штучной марки длиной 29 штрихкод из неё не берётся.
4. Нет открытой позиции и штрихкод товара есть — находится строка состава и открывается позиция. Нет карточки — «Товар со штрихкодом {штрихкод} не найден». Нет строки состава — «Товара {наименование} со штрихкодом {штрихкод} нет в составе этого документа!». После любого из этих двух текстов, если позиция так и не открылась, показывается «Сначала нужно отсканировать штрихкод товара!». Марка не пишется.
5. Позиция так и не открыта — «Сначала нужно отсканировать штрихкод товара!», марка не пишется. Упаковка `00` штрихкод товара из кода не берёт, поэтому без позиции останавливается здесь.
6. Та же марка в этом документе: «Эта марка уже отсканирована!».
7. Штрихкод из марки указывает на другой товар, чем открытая позиция: «Эта марка не для {наименование}! Штрихкод {штрихкод}».
8. Число единиц: палета — `ЕдиницВУпаковке` строки `pack_sizes` с `Паллета` истина; упаковка — строка с `Паллета` ложь; иначе `Коэффициент` штрихкода товара. Нет строки размера или карточки штрихкода — 1.
9. Подстановка упаковки True API, затем запрет индивидуальной марки в режиме «Упаковки».
10. Подобрано по строке — сумма `units` в `marks`. Нужно — `Количество` строки состава. Подобрано плюс единицы этой марки больше нужного — марка не пишется: «С этой маркой вы отсканируете больше чем нужно!».
11. Запись в `marks`. Позиция показывает новую сумму в «Подобрано». «Всего марок» остаётся `Количество` строки.
12. Сумма по строке равна `Количество` — позиция закрывается. Так по всем строкам состава — открывается меню и показывается «Все марки подобраны!».

Следующая марка по уже набранной строке снова получает «С этой маркой вы отсканируете больше чем нужно!».

«Удалить марку» принимает скан. Марка есть в `marks` — строка удаляется, позиция закрывается. Нет — «Такой марки нет в документе!».

Выгруженный документ марку не пишет и не удаляет. Скан показывает «Документ уже выгружен». Кнопка «Выгрузить документ» остаётся.

## База

Таблица `marks` в `main.db`. Ключ — `document_id` и `mark`. Колонки: `document_id`, `mark`, `nomenclature_uid`, `units`. Перед записью символ GS (код 29) в тексте марки заменяется на `\u001d`. Состав в `body` на скане не меняется.

В `documents` колонка `uploaded`, по умолчанию 0. Срок хранения удаляет марки удалённых документов. Справочники не удаляет.

`pack_sizes`: ключ — `nomenclature_uid` и `pallet`. `Паллета` ложь — упаковка, истина — палета. В пакете нет флага — это упаковка. Строка, записанная срезом загрузки с одним ключом на товар, остаётся упаковкой.

Колонка `search` удаляется. Журнал читает строки `documents` без `body` и отбирает поиск в Dart по `presentation`, `number` и `counterparty` без учёта регистра, включая кириллицу. Символы `%` и `_` ищутся как буквы.

## Выгрузка

«Выгрузить документ» открывает экран «Ожидание...». Подпись «Выгружаю документ {представление}». «Отмена» закрывает клиент и `uploaded` не меняет.

`POST {публикация}/dstsdapi/post`. Тело:

```json
{
  "Команда": "СборМарок",
  "Склад": "00000000-0000-0000-0000-000000000000",
  "Данные": {
    "УИДИС": "",
    "Тип": "СборМарок",
    "ТипДокументаErp": "",
    "Состав": []
  }
}
```

`УИДИС` — `erp_uid`. `ТипДокументаErp` — поле документа, если оно есть, иначе пустая строка. Элемент `Состав`: `Марка`, `Номенклатура`, `ГрупповойКод` (истина, когда `units` больше 1), `КоличествоЕдиниц`.

Успех HTTP — код 200, тело UTF-8. Успех выгрузки — `Пакет.Результат` истина. Тогда `uploaded` становится 1 и сбор закрывается. Отметка `uploaded` пишется до трёх раз: если запись в базу не удалась совсем, выгрузка всё равно считается успешной, потому что пакет уже на сервере, а повторная отправка создала бы второй документ. Повторная выгрузка шлёт тот же пакет, отметка остаётся 1.

`Пакет.Результат` ложь и в пакете есть `Ошибка` — «Обмен закончился неудачей по причиние: {ошибка}». Пустой `Пакет` — «Обмен закончился неудачей! Не получен пакет ответа». Ложь без текста ошибки — «Обмен закончился неудачей!». Другой код HTTP и сбой соединения — «Обмен закончился неудачей по причиние: {текст протокола}». `uploaded` при ошибке не меняется. Один `try/catch` в реализации команды.

## Журнал

Под `presentation` у документа с `uploaded` 1 пишется «Выгружен». У остальных эта строка пустая.

## Проверка

Тесты `flutter test` в `src/Presentation/TsdApp`:

- марка с `01` без открытой позиции открывает товар и пишет одну строку `marks`;
- марки документа не прочитались — подбор не открывается и скан показывает «Не удалось прочитать марки документа»;
- второй скан не пишется, пока первый ждёт запись в базу;
- упаковка `00` без позиции не пишет марку и возвращает «Сначала нужно отсканировать штрихкод товара!»;
- повтор марки, чужой товар, индивидуальная марка в режиме «Упаковки» и превышение `Количество` в базу не пишут;
- последняя марка документа открывает меню с текстом «Все марки подобраны!»;
- выгруженный документ скан не пишет и показывает «Документ уже выгружен», кнопка выгрузки пакет отправляет;
- `Пакет.Результат` истина ставит `uploaded` в 1; ложь отметку не ставит;
- сбой отметки после принятого пакета повторяет только отметку и не отправляет пакет второй раз;
- срок хранения удаляет марки документа и не удаляет справочник;
- журнал без колонки `search` находит кириллицу среди всех строк.
