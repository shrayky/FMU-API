# Протокол обмена ТСД

Срез после оболочки `docs/tsd-shell.md`. Проверка связи с сервером обмена. Загрузка документа, подбор марок и выгрузка сюда не входят.

Поля карточки общие для всех протоколов: адрес, порт, безопасное соединение, публикация, пользователь, пароль, таймаут. Новый протокол — другая реализация запросов, не другой набор полей.

## Протоколы

Интерфейс `ExchangeProtocol` в `domain/exchange/exchange_protocol.dart`. Метод проверки связи принимает `ExchangeServer` и отмену, возвращает успех и текст ошибки. Имени `Async` у метода нет. Отмена — объект домена: по ней реализация закрывает свой `http.Client`. Домен пакет `http` не импортирует.

Реестр `application/exchange/exchange_protocols.dart` знает два имени:

| На карточке | Класс | Поведение проверки |
|---|---|---|
| `DS TСД` | `infrastructure/exchange/ds_tsd_protocol.dart` | `GET {схема}://{адрес}:{порт}/{публикация}/dstsdapi/ping` |
| `Data Mobile` | `infrastructure/exchange/data_mobile_protocol.dart` | сеть не вызывается |

`DS TСД` — значение `defaultExchangeProtocol`, буква С кириллическая. Схема `https`, если на карточке включено безопасное соединение, иначе `http`. Сегмент публикации ставится между адресом и `dstsdapi/ping`; пустая публикация даёт путь `/dstsdapi/ping`. Заголовок basic-авторизации ставится всегда, в том числе при пустом пользователе. Таймаут — число секунд с карточки.

Успех ds-tsd — код ответа 200. Другой код и сбой соединения — ошибка. Текст ошибки попадает в сообщение на карточке.

Data Mobile забронирован: класс и строка реестра есть, контракта запросов нет. Проверка возвращает «Протокол Data Mobile ещё не подключён». Подключение протокола меняет этот класс. Карточка и реестр не меняются.

Поле «Протокол обмена» на форме сервера — выбор из этих двух значений, по умолчанию `DS TСД`. Свободного текста нет. Имя не из реестра, в том числе из старых настроек, в сеть не уходит.

## Экран проверки

«Проверить» открывает существующий экран «Ожидание...». Адресная строка остаётся `{адрес}:{порт}/{публикация}`.

«Отмена» закрывает HTTP-клиент, прерывает запрос и возвращает на карточку. Сообщение не показывается.

После ответа экран закрывается, карточка показывает диалог:

- успех — «Связь с сервером установлена»;
- ошибка — «Проверка связи завершилась с ошибкой: {текст}».

Ошибка обрабатывается один раз в реализации протокола.

Запрос не отправляется, и сразу возвращается ошибка, если:

- адрес пустой — «Не задан адрес сервера обмена»; порт 0 считается тем же случаем;
- таймаут 0 — «Не задан таймаут запроса»;
- протокол неизвестен — «Неизвестный протокол обмена».

## Проверка

Тесты `flutter test` в `src/Presentation/TsdApp`:

- реестр отдаёт `DS TСД` и `Data Mobile`;
- неизвестное имя не создаёт HTTP-клиент;
- ds-tsd на подменном `http.Client` собирает URL ping, передаёт basic-авторизацию, считает 200 успехом, а другой код — ошибкой;
- пустой адрес и таймаут 0 не вызывают сеть;
- Data Mobile сеть не вызывает и возвращает текст брони;
- отмена не показывает сообщение.

Клиент проверки марки `FmuApiClient` для этого запроса не используется.
