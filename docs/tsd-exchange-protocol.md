# Протокол обмена ТСД

Срез после оболочки `docs/tsd-shell.md`. Здесь контракт протокола и живая проверка связи. Загрузка документа, подбор, выгрузка, номенклатура, новая цена и токен True API в этом срезе по сети не вызываются: методы интерфейса для них есть, реализация ds-tsd возвращает «Команда ещё не подключена».

Поля карточки общие для всех протоколов: адрес, порт, безопасное соединение, публикация, пользователь, пароль, таймаут. Новый протокол — другая реализация запросов, не другой набор полей.

## Протоколы

Интерфейс `ExchangeProtocol` в `domain/exchange/exchange_protocol.dart`. Имени `Async` у методов нет. Отмена — объект домена: по ней реализация закрывает свой `http.Client`. Домен пакет `http` не импортирует. Общий результат вызова: успех, текст ошибки, тело ответа строкой. Разбор тела — срезы команд, не этот.

Реестр `application/exchange/exchange_protocols.dart` знает два имени:

| На карточке | Класс |
|---|---|
| `DS TСД` | `infrastructure/exchange/ds_tsd_protocol.dart` |
| `Data Mobile` | `infrastructure/exchange/data_mobile_protocol.dart` |

`DS TСД` — значение `defaultExchangeProtocol`, буква С кириллическая. Схема `https`, если на карточке включено безопасное соединение, иначе `http`. Сегмент публикации ставится между адресом и `dstsdapi`; пустая публикация даёт путь `/dstsdapi/...`. Заголовок basic-авторизации ставится всегда, в том числе при пустом пользователе. Таймаут — число секунд с карточки. Успех HTTP — код 200. Другой код и сбой соединения — ошибка, тело ответа сохраняется в тексте ошибки.

Data Mobile забронирован на все методы: сеть не вызывается, результат «Протокол Data Mobile ещё не подключён». Подключение протокола меняет этот класс. Карточка и реестр не меняются.

Поле «Протокол обмена» на форме сервера — выбор из этих двух значений, по умолчанию `DS TСД`. Свободного текста нет. Имя не из реестра, в том числе из старых настроек, в сеть не уходит.

Загрузка номенклатуры по выбранным группам в модуле `ApiDsTsdКлиентСервер` пустая, HTTP-контракта нет. В интерфейс не входит.

## Команды ds-tsd

| Метод | Запрос | Тело | В этом срезе |
|---|---|---|---|
| проверка связи | `GET dstsdapi/ping` | нет | выполняется |
| документ по штрихкоду | `GET dstsdapi/get?Команда={команда}&Штрихкод={штрихкод}` | нет | контракт |
| статус марки | `GET dstsdapi/get?Команда=СтатусСбораМарки&Марка={марка}` | нет | контракт |
| токен True API | `GET dstsdapi/get?Команда=ТокенТруАпи` | нет | контракт |
| номенклатура | `GET dstsdapi/get?Команда=goods` | нет | контракт |
| выгрузка документа | `POST dstsdapi/post` | JSON ниже | контракт |
| новая цена | `POST dstsdapi/post?Команда=setPrice` | JSON ниже | контракт |

Документ сбора запрашивается командой `СборМарокПоДокументу`. Метод принимает команду строкой, чтобы тот же вызов годился для другого типа документа.

Выгрузка документа:

```json
{
  "Команда": "СборМарок",
  "Склад": "00000000-0000-0000-0000-000000000000",
  "Данные": {
    "УИДИС": "",
    "Тип": "",
    "ТипДокументаErp": "",
    "Состав": []
  }
}
```

Новая цена. В адресе команда `setPrice`, в JSON команда другая:

```json
{
  "Команда": "НоваяЦенаПозиции",
  "Данные": {
    "Номенклатура": "",
    "Цена": 0
  }
}
```

Токен True API при успехе читает из тела поля `Токен` и `ДействуетДо`. `ДействуетДо` — дата ISO 8601. Если срок уже прошёл, результат ошибки — «Срок полученого токена истек!». Если в настройках задан адрес сервиса проверки марок, 1С берёт токен у этого сервиса, а не у протокола. Обход в этом срезе не делается.

Номенклатура `goods`: тело 200 — JSON с полем `Пакет`, а `Пакет` — строка JSON со справочниками `Номенклатура` и `Штрихкоды`. Разбор пакета — срез загрузки номенклатуры.

Неподключённая команда ds-tsd сеть не вызывает и возвращает «Команда ещё не подключена».

## Экран проверки

«Проверить» открывает существующий экран «Ожидание...». Адресная строка остаётся `{адрес}:{порт}/{публикация}`.

«Отмена» закрывает HTTP-клиент, прерывает запрос и возвращает на карточку. Сообщение не показывается.

После ответа экран закрывается, карточка показывает диалог `MessageDialog` (правила сообщений — `docs/tsd-messages.md`):

- успех — «Связь с сервером установлена», иконка `check_circle_outline` цветом `ok`;
- ошибка — «Проверка связи завершилась с ошибкой: {текст}», иконка `error_outline` цветом `warn`;
- проверка не ушла в сеть (адрес, таймаут, протокол) — тот же текст ошибки, иконка `warning_amber_rounded` цветом `warning`.

Текст ошибки готовит реализация протокола, а не форма. `describeFailure` в `domain/message/failure_text.dart` переводит сбой в русский текст: таймаут — «Сервер не ответил за 10 сек» без микросекунд, отказ соединения и поиск хоста — своим текстом, код не 200 — «Сервер ответил кодом {код}: {первая строка тела}». Сырое исключение и тело остаются в `details` результата и в `payload` записи журнала (`endpoint` и `raw`, строка обрезается до 2000 символов), в диалог они не попадают.

Каждое сообщение пишется в «Логи работы» уровнем по виду: успех — `info`, ошибка — `error`, ошибка валидации — `warning`. Ошибка сопровождается системным сигналом и сильной вибрацией, успех — щелчком, предупреждение — средней вибрацией.

Ошибка обрабатывается один раз в реализации протокола.

Запрос не отправляется, и сразу возвращается ошибка, если:

- адрес пустой — «Не задан адрес сервера обмена»; порт 0 считается тем же случаем;
- таймаут 0 — «Не задан таймаут запроса»;
- протокол неизвестен — «Неизвестный протокол обмена».

## Проверка

Тесты `flutter test` в `src/Presentation/TsdApp`:

- реестр отдаёт `DS TСД` и `Data Mobile`;
- неизвестное имя не создаёт HTTP-клиент;
- ds-tsd на подменном `http.Client` собирает URL ping, передаёт basic-авторизацию, считает 200 успехом, а другой код — ошибкой;
- код не 200 даёт текст «Сервер ответил кодом 503: нет» и тело в подробности;
- таймаут даёт «Сервер не ответил за 10 сек», сырой текст остаётся в подробности;
- пустой адрес и таймаут 0 не вызывают сеть;
- остальные команды ds-tsd сеть не вызывают и возвращают «Команда ещё не подключена»;
- Data Mobile на любом методе сеть не вызывает и возвращает текст брони;
- отмена проверки связи не показывает сообщение;
- ошибка проверки показывается диалогом с иконкой и пишется в журнал работы.

Клиент проверки марки `FmuApiClient` для этих запросов не используется.
