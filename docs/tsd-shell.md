# Оболочка задач ТСД

Срез 1 переноса сбора марок из мобильной 1С (`Ds-Check-Mark`) в `src/Presentation/TsdApp`. Главный экран — меню задач. Проверка марки — отдельный экран. Экраны ниже зафиксированы по согласованным примерам. Данные документа, правила подбора и сам запрос к серверу обмена в этот срез не входят: экраны их показывают, когда данные появятся в следующих срезах.

## Граница среза

В срезе есть меню, реестр задач, настройки, экраны сбора, журнала, проверки марки и карточки серверов обмена.

Следующие срезы, поведение которых здесь не реализуется:

- протокол обмена и проверка связи — в `docs/tsd-exchange-protocol.md`; экраны сервера уже есть, запрос ping этим документом оболочки не описывался;
- загрузка документа по штрихкоду и локальное хранение;
- правила подбора марок и выгрузка документа;
- полная загрузка номенклатуры, True API, новая цена, Anydesk;
- проверка пин-кода: поле на экране есть, запрос пина при входе в настройки нет.

Непрерывное сканирование и intent остаются в `AppSettings`. На согласованных вкладках настроек для них места нет.

## Тема

Цвета `WebixDarkTheme`: фон `#2A2B2D`, панели `#20262B`, текст `#E6FFFFFF`, подписи `#9CA3AF`, акцент `#60A5FA`. Команды — обычный текст. Акцент у выбранной вкладки, названия задачи, значка журнала, ссылок, режима «Упаковки» / «Единицы», «Создать», «Проверить» и «Ок». Коралловый на экранах не используется.

Кнопка камеры — существующий `FloatingActionButton`: акцент `#60A5FA`, `Icons.qr_code_scanner`. Стоит справа, сразу над нижней панелью. Видна, когда включено «Сканирование камерой мобильного устройства». Одна и та же на шапке сбора, позиции, проверке марки и экране удаления марки. На меню её нет.

## Меню

`HomeScreen` — меню. Заголовок «Fmu-Api v {версия}». Сканер на меню выключен.

Нижняя панель: Документы, Обмен, Настройки, Выход. Сервис добавляется между Документами и Обменом, только когда в нём есть включённая задача. Содержимое вкладки «Обмен» на меню примером не задано. Выход закрывает приложение.

На Документах строка задачи — акцентная подпись на всю ширину. У «Сбор марок» справа кнопка журнала: блокнот с тремя строками и закладкой снизу. У «Проверка марки» журнала нет. Горячая клавиша на строке не пишется.

На меню остаются поиск Fmu-Api при пустом `apiBaseUrl`, баннеры поиска и пустого адреса, предложение обновить приложение и баннер ошибки проверки обновления. Таймер обновления живёт на меню и идёт, пока поверх открыта задача.

## Задача

`domain/task/tsd_task.dart`. Оболочка не знает экраны задач.

| Поле | Смысл |
|---|---|
| `id` | стабильный код |
| `defaultTitle` | подпись, если в настройках пусто |
| `defaultSection` | `documents` или `service` |
| `hasJournal` | у задачи есть журнал |
| `open` | экран задачи, аргумент — текущие `AppSettings` |
| `openJournal` | экран журнала; только при `hasJournal` |

`application/shell/task_registry.dart`:

| id | Подпись | Раздел | Журнал | Экран |
|---|---|---|---|---|
| `markCollection` | Сбор марок | `documents` | да | экран сбора |
| `markCheck` | Проверка марки | `documents` | нет | `MarkCheckScreen` |

Новая задача добавляется в реестр. Меню из-за неё не меняется.

## Кнопки

`domain/task/task_button.dart`: `taskId`, `section`, `title`, `order`, `hotkey`, `showJournal`, `enabled`.

`application/shell/task_buttons.dart`:

- нет сохранённых кнопок — «Сбор марок» (`order` 1, журнал включён) и «Проверка марки» (`order` 1, журнал выключен), обе в `documents` и включены;
- неизвестный `taskId` отбрасывается;
- известная задача без строки получает значение по умолчанию;
- выключенные скрыты;
- внутри раздела сортировка по `order`, затем по подписи;
- пустая подпись заменяется на `defaultTitle`;
- горячая клавиша длиннее одного символа не срабатывает;
- журнал рисуется, когда `hasJournal` и `showJournal`.

Пустой раздел на нижнюю панель не попадает. Если включённых кнопок нет, тело меню — «Все задачи выключены».

Клавиши, пока меню в фокусе: символ горячей клавиши открывает задачу без учёта регистра. При двух совпадениях открывается первая в порядке раздела Документы, затем Сервис, внутри раздела по `order` и подписи. Поверх меню фокус у задачи, клавиши меню не обрабатываются.

## Настройки

Заголовок «Настройка Fmu-Api». Нижняя панель с иконкой и подписью, как у меню и сбора: Основные, Оборудование, Задачи, Обмен, Выход. Выход возвращает в меню.

Кнопки задач входят в `AppSettings` и пишутся в `SharedPreferences` ключом `taskButtons`. Битый JSON и пустое значение дают набор по умолчанию. На примерах отдельной кнопки «Сохранить» нет: поля вкладок хранятся в настройках приложения. Пустой или нечисловой порядок сохраняется как 1. Горячая клавиша — один символ или пустая строка. Повтор символа не закрывает редактор строки и показывает «Такая горячая клавиша уже задана».

Основные:

- «Сервер обмена» — выбранное наименование, пример «КД»; открывает список серверов;
- «Пин код настроек»;
- группа «Документ Сбор марок»: «Регистрация штрихкода упаковок (по умолчанию)», «Проверять владельца марки», «Запрос статуса подбора марки», «Запрашивать упаковку марки по true api»; в примере все включены;
- группа «Сервис проверки марок»: адрес, пример `http://10.10.10.41:2578`, и «Апи для проверки марки» со значением «True api»;
- «Логи работы».

Оборудование: только «Сканирование камерой мобильного устройства». Модели ТСД, DS.Keyboard и приложения сканера на вкладке нет.

Задачи: «Добавить задачу» открывает «Форма задачи». Колонки списка «Экран задачи ТСД / Экран» и «Горячая клавиша». Строки примера: «Сбор марок / Основной», «Проверка марки / Основной». На форме: «Экран задачи ТСД» (выбор из реестра), «Представление», «Экран» с двумя значениями — «Основной» (раздел Документы) и «Дополнительный» (раздел Сервис), «Показывать журнал» флажком, «Горячая клавиша», «Порядок» со значением 0. Внизу «Закрыть» обычным текстом и «Ок» акцентом, оба возвращают к списку. Задачу вне реестра выбрать нельзя. Журнал на меню есть, только если у задачи в реестре есть журнал и флажок включён.

Обмен: «Добавить вариант обмена» открывает «Форма варианта обмена». Колонки списка «Операция» и «Порядок / Горячая клавиша». Строка примера: «Загрузка номенклатуры», порядок 0, горячая клавиша 1. Операция на форме одна — «Загрузка номенклатуры». Дальше «Порядок» со значением 0, «По умолчанию» выключено, «Горячая клавиша» со значением 0. Внизу «Закрыть» и «Ок», как на форме задачи. Сама загрузка номенклатуры этим срезом не выполняется.

## Серверы обмена

Их несколько. Список «Сервера обмена» открывается с поля «Сервер обмена». Строка — наименование, у примера `vostok` второй строкой `10.11.12.178:80/ideal1`. Выбор строки подставляет наименование в «Сервер обмена» и возвращает в Основные. Внизу «Создать» (акцент) и «Закрыть» (обычный текст). «Закрыть» возвращает в настройки.

«Создать» открывает «Сервер обмена (создание)». Поля сверху вниз: Наименование, IP-адрес, Порт, Безопасное соединение, Имя публикации базы, Пользователь, Пароль, Таймаут запроса (сек), Протокол обмена. Пример заполнения: `vostok`, `10.11.12.178`, `80`, безопасное соединение выключено, `ideal1`, `tsd_token`, таймаут `300`, протокол «DS TСД». Внизу «Проверить» (акцент) и «Закрыть» (обычный текст). «Закрыть» возвращает к списку.

«Проверить» открывает ожидание на весь экран. Заголовок «Ожидание...». Текст «Проверка связи с сервером» и строка `{IP}:{порт}/{публикация}`. Внизу «Отмена» обычным текстом — возврат к карточке без результата. Сам запрос в этом срезе не отправляется.

## Проверка марки

`presentation/mark_check/mark_check_screen.dart` забирает текущий сценарий `HomeScreen`: фокус, intent, буфер обмена, камера, карточка марки, непрерывное сканирование, запрос ИНН и `api/ts/checkMark`. Адрес читается из настроек. Пустой адрес показывает «Укажите адрес Fmu-Api в настройках». Своего поиска адреса и своей проверки обновления нет. Своей кнопки настроек нет.

Заголовок «Проверка марки». Пустой экран — «Сканируйте марку». Нижняя панель: «Очистить» сбрасывает карточку к этому тексту, «Выход» возвращает в меню.

## Сбор марок

Заголовок «Сбор марок». Нижняя панель: Шапка, Состав, Позиция, Меню, Выход. Выход возвращает в меню.

Шапка: «Для начала подбора марок отсканируйте QR код на документе».

Состав. Колонки «Наименование / Количество» и «Количество марок». Пусто: «Нет данных для отображения». Пример строки: «Вода негазированная 0,5 л», количество 12, марок 1. «Удалить марку» прижата к нижней панели и открывает экран «Удаление марки»: «Отсканируйте марку» и внизу «Отмена». «Отмена» возвращает в состав без изменений. После скана соответствующие данные убираются из таблицы. В примере строка одна, остаётся «Нет данных для отображения».

Позиция без открытого товара: «Отсканируйте штрихкод товара». «Закончить подбор» неактивна. После скана товара сверху две карточки: «Всего марок» — количество строки, «Подобрано» — число уже отсканированных марок этой строки. Под ними наименование на оставшуюся высоту. В примере 12, 1 и «Вода негазированная 0,5 л». Над нижней панелью две команды: «Закончить подбор» закрывает товар и возвращает приглашение, «Упаковки» переключает подпись на «Единицы» и обратно.

Меню: заголовок «Операциии с документом» и кнопка «Выгрузить документ» цветом обычного текста. Выгрузка в этом срезе не выполняется.

## Журнал

Открывается кнопкой у «Сбор марок». Слева «Закрыть» — возврат в меню, затем поиск, заголовок «Сбор марок», справа «+» — новый сбор. Колонки «Документ / Выгружен», «Номер», «Дата». Пусто: «Нет данных для отображения».

## Ошибки

Поиск Fmu-Api и проверка обновления на меню ведут себя как сейчас: сеть недоступна — баннер адреса или баннер сбоя обновления, меню остаётся рабочим. Экран проверки при ошибке запроса показывает ту же карточку ошибки, что и сейчас.

## Проверка

Юнит-тесты `task_buttons`: значения по умолчанию обе в `documents`, отбрасывание неизвестного кода, подмешивание отсутствующей задачи, скрытие выключенных, сортировка, пустая подпись, журнал только при обоих флагах, горячая клавиша длиннее одного символа.

Виджет-тесты меню: на Документах обе задачи, у сбора есть журнал, Сервис скрыт, на меню нет `ContinuousScanTable` и кнопки камеры, пустой набор показывает «Все задачи выключены», горячая клавиша открывает проверку марки.

Существующие тесты `widget_test.dart`, которые открывают проверку марки, непрерывный режим, камеру и буфер обмена, переносятся на `MarkCheckScreen`. Поиск адреса и баннер обновления проверяются на `HomeScreen`.
