# Сообщения и журнал работы ТСД

Срез после проверки связи `docs/tsd-exchange-protocol.md`. Здесь один путь вывода сообщений: текст по бизнес-правилам, запись в журнал, звук и внешний вид. Новые экраны не рисуют `AlertDialog` и `SnackBar` сами, а зовут `MessageCenter`.

## Правила сообщений

`application/message/message_center.dart` — единственная точка вывода. Сообщение собирается в домене (`domain/message/app_message.dart`): вид `MessageKind`, текст, необязательный заголовок и JSON-подробности `data` для журнала.

| Вид | Иконка | Цвет | Звук и вибрация | Уровень журнала |
|---|---|---|---|---|
| `success` | `check_circle_outline` | `WebixDarkTheme.ok` | щелчок | `info` |
| `failure` | `error_outline` | `WebixDarkTheme.warn` | сигнал и сильная вибрация | `error` |
| `warning` | `warning_amber_rounded` | `WebixDarkTheme.warning` | средняя вибрация | `warning` |
| `info` | `info_outline` | `WebixDarkTheme.accent` | нет | `info` |

Диалог — `presentation/shell/message_dialog.dart`: иконка, текст и кнопка «Ок» цветом `accent` на подложке `dialogSurface`. Баннер снизу (`showSnack`) берёт те же иконку и цвет.

`MessageCenter` собирает тексты проверки связи: `exchangeProbe` — успех или ошибка протокола, `exchangeBlocked` — проверка не ушла в сеть. Подробности ошибки — `endpoint` `{хост}:{порт}/{публикация}` и `raw` — сырой ответ или исключение.

Звук и вибрацию даёт `application/message/message_effects.dart`. Это единственное место вызова `SystemSound` и `HapticFeedback`, поэтому в тестах правила подменяются.

## Тексты сбоев

`domain/message/failure_text.dart`:

- `describeFailure(error)` — текст сбоя для человека. Понимает `TimeoutException`, отказ соединения, поиск хоста, обрыв, TLS и порт; неизвестный текст возвращает как есть;
- `describeTimeout(duration)` — «500 мс», «10 сек», «1 мин 30 сек», «2 ч 5 мин». Микросекунды из `TimeoutException after 0:00:10.000000` в диалог не попадают;
- `describeHttpStatus(code, body)` — «Сервер ответил кодом 503: нет», тело длиннее 200 символов обрезается.

Сырой текст исключения остаётся в `ExchangeCallResult.details` и в журнале, а не в диалоге.

## Журнал

Журнал живёт в отдельной базе `journal.db` — файлом рядом с базой документов. Две базы намеренно разные: сбой или блокировка основной базы не уносит журнал, а журнал не конкурирует с документами за запись.

`infrastructure/journal/journal_database.dart` открывает файл и создаёт схему версии 1:

```sql
CREATE TABLE work_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  at INTEGER NOT NULL,
  level TEXT NOT NULL,
  text TEXT NOT NULL,
  payload TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX work_log_at ON work_log(at DESC);
```

`payload` — JSON со структурными подробностями (`endpoint`, `raw`, `error`, `barcode`). Новые поля не требуют миграции: старые записи просто без них.

`infrastructure/journal/sqlite_work_log_storage.dart` — `WorkLogStorage` на этой таблице: `recent`, `add`, `trim`, `clear`. `trim` удаляет записи старше срока и всё, что не влезло в лимит строк.

`application/journal/work_log.dart` — `WorkLog`, общий экземпляр `WorkLog.instance`. Память держит последние 300 записей для экрана, база — 7 дней или 5000 записей, что наступит раньше. Чистка идёт при открытии журнала и раз в 25 записей. Строковые значения в `payload` обрезаются до 2000 символов: тело ответа 1С бывает очень большим. Ошибка базы журнал не ломает: записи остаются в памяти, а экран показывает то, что успело прочитаться.

Экран «Логи работы» (`presentation/settings/work_log_screen.dart`) показывает записи от новых к старым: иконка уровня, текст, до трёх строк подробностей в виде `ключ: значение` и время `ДД.ММ чч:мм:сс`. Пусто — «Нет данных для отображения». Внизу «Очистить» (только при записях) и «Закрыть».

## Где подключено

| Экран | Сообщение |
|---|---|
| карточка сервера обмена | диалог результата проверки связи |
| настройки, «Найти в сети» | баннер «Fmu-Api в сети не найден» |
| проверка марки | баннер «Это не марка» |
| меню, установка обновления | баннер сбоя установки |

Баннер «Укажите адрес Fmu-Api в настройках» остаётся частью экрана, а не сообщением. Сбой проверки обновления не показывается вовсе: меню работает, следующая проверка идёт по таймеру.

## Проверка

Тесты `flutter test` в `src/Presentation/TsdApp`:

- `failure_text_test` — таймаут в секундах и минутах, сетевые сбои, неизвестный текст, код ответа и обрезка тела;
- `work_log_test` — порядок записей, предел памяти, загрузка без потерь, обрезка JSON и очистка;
- `work_log_screen_test` — записи видны вместе с подробностями, очищаются, пустой журнал показывает заглушку;
- `sqlite_work_log_storage_test` — схема, порядок и лимит выборки, JSON обратно, `trim` по возрасту и строкам, `clear`;
- `message_center_test` — текст, иконка, уровень журнала и звук для успеха, ошибки, предупреждения и баннера;
- `exchange_probe_screen_test` — диалог проверки пишет запись в журнал и показывает иконку.
